# 緑特の型（数え方の修正と、役割・ポジションごとの付き方） 改修指示

## 目的

1. **球団分析の緑特の数え方を、実在と同じにする**。生成の「調子極端・調子安定・投球位置・慎重盗塁」を緑特に数えているが、実在ではこれらは起用法の欄にあり、緑特に数えていない。投手の緑特が多く見える原因の半分以上はこれ。
2. **緑特の付き方を、投手は役割（先発・救援）、野手はポジションごとに実在に合わせる**。実在は、救援に速球中心が多く、先発にテンポ○が多い。一塁手に強振多用、二遊間にミート多用・積極守備が多い。生成はどの役割・ポジションでも同じ割合で付いている。

対象は架空球団用の日本人の投手・野手（個別生成・球団生成の両方）。外国人・ドラフト候補用、青特・赤特、能力・ランク特能は変えない。

**前提**: PR #117 をマージした後の main（57ed460）で作業する。PR #117 の「青特の型」の仕組み（`fictional_special_profile_adjust`、`scripts/build_fictional_special_profile.py`）を広げて使う。

## 1. 改修の内容

### 1-1. 球団分析の数え方
- `generator/team_analysis.py` で生成の選手の特能を数えるとき、次の特能は**どの色にも数えない**（実在の起用法と同じ扱い）。
  - 投手調子極端・投手調子安定・野手調子極端・野手調子安定・投球位置左・投球位置右・慎重盗塁・フル出場
- `special_color` は、マスターにない種類を青に数える作りになっている。これらを緑から外したとき、**青に回らないようにする**。
- 一覧は1か所にまとめ、理由（実在では起用法の欄にあるため）をコメントに書く。
- 同じ数え方をしている箇所（球団分析画面、`validate_team_mode.py`、出力など）がほかにもあれば、同じように直す。直した箇所を一覧で報告する。
- 生成は変えない。

### 1-2. 緑特の型の補正
PR #117 の `fictional_special_profile_adjust` と同じ仕組みで、緑特の保有率を区分ごとに実在に寄せる。

- 区分:
  - 投手: 投げ手 × 役割（`左|先発`、`右|救援` など。中継ぎ・抑えは救援）。青特の区分（投げ手だけ）とは別。
  - 野手: 青特と同じ「ポジション|打席」。
- 対象の特能:
  - 投手: 変化球中心・速球中心・テンポ○
  - 野手: 積極打法・慎重打法・強振多用・ミート多用・チームプレイ○・積極走塁・積極守備
  - 選球眼・積極盗塁（能力と連動）、慎重盗塁・調子・投球位置（起用法）は対象にしない。
- 目標の水準は**実在の全体の保有率**にする（青特と違い、全体の水準も実在に寄せる）。
- 区分ごとの倍率の作り方は、PR #117 の 1-6 と同じ（`w = n/(n+60)` で縮め、投手は 投げ手の倍率 × 役割の倍率、野手は ポジションの倍率 × 打席の倍率。生成の区分の人数の割合で平均したとき水準と同じになるようにそろえる。1回だけ結果を見て直す）。
- 表は `scripts/build_fictional_special_profile.py` で作り、同じ設定ファイルの別の節（例: `"緑"`）か、別のファイルに置く。
- 段階は `fictional_special_profile_adjust`（青特）の**後**。乱数は**新しい名前空間の副乱数**（例: `"fictional_green_profile_v1"`）から、表の特能ごとに1回ずつ引く。青特の段階の乱数の並びを変えないため。
- 年齢の重み: 緑特は年齢でよく増える（実在の緑特の数、〜21歳 → 34歳以上: 野手 0.6 → 1.7、投手 0.2 → 0.75）。足すときは実在の緑特の年齢による比で重みをかけ（生成の年齢の分布で平均1）、外すときは年長ほど外しにくくする。`check_age_profile.py` の緑特の判定を崩さないため。
  ```
  足す重み（比）: 野手 20歳 0.50、23.5歳 0.74、27.5歳 1.16、31.5歳 1.49、36歳 1.40（÷1.03）
                  投手 20歳 0.58、23.5歳 0.70、27.5歳 1.00、31.5歳 1.36、36歳 2.27（÷1.039）
  外す重み（試作）: (1 / 足す重みの比) の 0.7乗、上限 1.8
  ```
- 足すときは `fictional_set_special(..., force=False)`（速球中心と変化球中心、強振多用とミート多用、積極打法と慎重打法は同じグループなので、両方は付かない）。特能数の上限・下限を守る。

## 2. 判定

### 2-1. 新しい判定（球団生成300球団、架空球団用の日本人）
PR #117 の `scripts/check_special_profile.py` に節を足す。PR #110 の仕組み（「実在」の判定、誤差つきの合否、id）で作る。

| 項目 | 合格の範囲 |
|---|---|
| 緑特の数（1-1 の数え方） 投手 | 実在±0.05 |
| 緑特の数（1-1 の数え方） 野手 | 実在±0.10 |
| 1-2 の対象の特能の、区分（投手は役割、野手はポジション）ごとの保有率 | 実在±0.06（人数の少ない区分は誤差つきで判定） |
| 速球中心の 救援−先発、テンポ○の 先発−救援 | 実在±0.05 |

- 個別生成（架空球団用・投手と野手 各5000人）は参考として同じ表を出す。

### 2-2. 既存の判定の扱い
- `run_checks.py` を正式な規模で、全スクリプトを単独で流す。
- 1-1 の数え方の修正で、球団分析を使う判定（`validate_team_mode.py` など）の緑特・青特の値が動くのは想定内。1-2 で特能・査定・背番号が動くのも想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけ `--update-snapshot --only ... --reason` で更新する。値が動いたスクリプトは漏れなく更新し、最後に悪化0・改善0を確かめる。
- 動いてはいけない項目（能力・弾道・変化球・ランク特能、青特・赤特の数、外国人・ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定:
  - `check_age_profile.py` の年齢帯ごとの緑特の数と年齢との相関。
  - `check_special_profile.py` の青特の判定（PR #117）がそのまま合格すること。
  - `check_fictional_balance.py` の特能の出現率・特能数の分布。
- 「固定」の基準値を更新する場合は `--update-baselines --only` で項目を絞り、理由を付ける。

### 2-3. 変わらないことの確認
- 助っ人外国人用・ドラフト候補用の投手と野手: seed 1〜1000 で完全に一致。
- 架空球団用の投手と野手: 名前・年齢・ポジション・投打・身長・体重・能力・弾道・変化球・ランク特能が改修前と一致する。変わった項目を人数つきで一覧にする（緑特が変わった人数、特能から決まる査定など）。
- 1-1 の数え方の修正だけを入れた状態で、生成の結果（seed 1〜1000）が改修前と完全に一致することも確かめる。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
