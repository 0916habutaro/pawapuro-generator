# 青特の型（投手の左右・野手の打席とポジション） 改修指示

## 目的

架空球団用の日本人の**青特の付き方**を実在に合わせる。

- 実在は**左投手のほうが青特が多い**（左 3.35、右 2.59）。生成は差がない（左 2.79、右 2.91）。
- 実在は**左打者のほうが青特が多い**（左 2.78、右 2.16）。生成は差が小さい（左 2.41、右 2.29）。
- ポジションでは、**捕手が多すぎ**（実在 1.72、生成 2.19）、一塁・二塁・外野が少ない。#115 で残った捕手の査定 +6 の原因。

対象は架空球団用の日本人の投手・野手（個別生成・球団生成の両方）。外国人・ドラフト候補用は変えない。能力・ランク特能は変えない。

**前提**: 「対ランナー」の取り違えの修正（PR #116）をマージした後の main（06bb1c7）で作業する。この指示書の実在の値は、その修正をした後の数え方で出している。

---

## 0. 調査の結果

球団生成300球団（seed 1〜300、`PYTHONHASHSEED=0`、main 81c0511）の日本人と、実在（2024〜2026年版の日本人）を比べた。青特の数は、球団分析と同じ数え方（マスターの `kind` が red・green・gold 以外）。実在の「○○キラー」（球団名の付く特能。架空球団では出せない）は数えない。

### 0-1. 青特の数

| | 実在 | 生成 |
|---|---|---|
| 投手 左／右 | 3.35／2.59 | 2.79／2.91 |
| 野手 全体 | 2.45 | 2.34 |
| 野手 左打／右打 | 2.78／2.16 | 2.41／2.29 |
| 捕手／一塁／二塁／三塁／遊撃／外野 | 1.72／2.83／2.82／2.47／2.33／2.80 | 2.19／2.32／2.41／2.25／2.36／2.45 |

### 0-2. 原因

1. **特能ごとの左右・ポジションの差が入っていない**。実在で差が大きい特能の例（実在 → 生成）:
   - 投手: クロスファイヤー 左18.6%・右0% → 左5.0%・右5.1%、緩急○ 左26%・右9% → 16%・17%、球持ち○ 左35%・右16% → 25%・25%、内角攻め、牽制○、ナチュラルシュート（右が多い）。
   - 野手: サヨナラ男・カット打ち・インコースヒッター・レーザービームは左打が多い。捕手はバント○・ホーム死守が多く、固め打ち・決勝打が少ない。一塁手は流し打ち・決勝打・プルヒッターが多い。
2. **能力と連動させている特能（`FICTIONAL_LINKED_SPECIALS`）が、投打を見ていない**。同じ能力でも実在は左のほうが多い。
   - 奪三振（球速の帯ごと、実在 右／左）: 〜147 5%／13%、〜151 13%／24%、〜155 21%／55%、156〜 61%／83%。生成は左右同じ。
   - 内野安打○（走力）: 〜70 4%／7%、〜80 25%／40%、81〜 41%／71%。
   - 広角打法（ミート）: 実在は右打だけに多い（〜50 右11%・左2%、51〜 右19%・左7%）。
3. **実在の日本人（2024〜2026）にいない特能を生成が出している**: 投手のムード○（2.1%）・投打躍動（1.2%）・全開（1.1%）、野手の対エース○（1.8%）・ブロッキング（1.4%）・フレーミング○（1.0%）・フレーミング◎（0.6%）。捕手の青特が多い一因。プレッシャーランも多い（生成 2.6%、実在 0.3%）。
4. **特能マスターにない特能**: 実在の野手にはお祭り男 4.1%・春男 1.9%・夏男 1.6%・秋男 0.5% がある（査定表にはある）。生成では出せないため、野手の青特が約0.08少ない。
5. **「対ランナー」**: 生成は青の「対ランナー」（＝対ランナー○）が約5%で、実在（約2%）より多い。赤の「対ランナー×」は「実在にない特能」として外しているが、実在に約8.6%ある。

## 1. 改修の内容

### 1-1. 特能マスターに4つ足す
- お祭り男・春男・夏男・秋男を、野手の青特として `data/special_abilities.csv` に足す（`kind=blue`、`power=normal`、**`weight=0`**、`target_role=野手`、それぞれ別のグループ）。
- `weight=0` なので、ほかの区分（ドラフト候補用・外国人）では出ない。架空球団用は 1-5 で付ける。
- 特殊能力の表示順の並び（`特殊能力表示順_改修指示.md`）があれば、そこにも入れる。査定表には既にある。

### 1-2. 実在にいない特能を外す
`FICTIONAL_NOT_REAL_SPECIALS` に足す。
- 投手: ムード○、投打躍動、全開
- 野手: 対エース○、ブロッキング、フレーミング○、フレーミング◎

### 1-3. 「対ランナー」
- `FICTIONAL_AGE_NEGATIVE_SPECIALS` の「対ランナー」を「対ランナー×」にする（今は生成の青の対ランナーを赤として扱っている）。
- 青の「対ランナー」と赤の「対ランナー×」の保有率は、1-5 で実在に合わせる。赤の「対ランナー×」は「実在にない特能」の一覧に残したまま（最初の抽選では出さない）、1-5 だけで付ける。

### 1-4. 能力と連動させる特能に投打の差を入れる
- `FICTIONAL_LINKED_SPECIALS` の保有率を、投打ごとに上書きできるようにする（例: `FICTIONAL_LINKED_HAND_RATES`）。投手は投げ手、野手は打席（両打は右打と同じ）で決める。
- `fictional_adjust_specials` と、`fictional_age_adjust_specials` の連動の比（`linked`）の両方で、同じ投打の保有率を使う。
- 乱数の引く回数は変えない。

```
奪三振（球速 〜147／〜151／〜155／156〜）: 右 0.055／0.135／0.215／0.62、左 0.135／0.25／0.55／0.75
内野安打○（走力 〜70／〜80／81〜）:        右 0.045／0.27／0.43、左 0.07／0.42／0.75
広角打法（ミート 〜40／〜50／51〜）:        右 0.01／0.12／0.20、左 0.012／0.02／0.075
```

### 1-5. 青特の型の補正（新しい最後の段階）
- `fictional_age_adjust_specials` の**後**に、特能ごと・区分ごとの保有率を実在に寄せる段階を足す（投手・野手とも）。ランク特能の前。
- 区分は、投手は投げ手（左・右）、野手はポジション × 打席（両打は右打）。
- 特能ごと・区分ごとに「今の保有率 `c`」と「目標の保有率 `t`」を持つ表を使う。
  - 持っていて `t < c` なら、確率 `1 − t/c` で外す。
  - 持っていなくて `t > c` なら、確率 `(t − c)/(1 − c) × 年齢の重み` で足す。年齢の重みは、実在の青特の数の年齢による比（下）を、生成の年齢の分布で平均1にしたもの。年齢の傾き（`check_age_profile.py` の判定）を崩さないため。
    ```
    野手: 20歳 0.44、23.5歳 0.76、27.5歳 1.20、31.5歳 1.34、36歳 1.78（÷1.054）
    投手: 20歳 0.65、23.5歳 0.85、27.5歳 1.18、31.5歳 1.32、36歳 1.46（÷1.064）
    ```
  - 足すときは `fictional_set_special(..., force=False)` を使う（同じグループ・矛盾の組み合わせ・位置の条件を守る）。選手格の特能数の上限・下限（`special_count_bounds`）を超えない。
- **右投手のクロスファイヤーは必ず外す**（実在は0人）。下限に関係なく外す。
- 乱数は**新しい名前空間の副乱数**（例: `make_sub_rng(seed, "fictional_special_profile_v1")`）から、表の特能ごとに1回ずつ引く。ほかの抽選の乱数の並びを変えないため。

### 1-6. 目標の表の作り方
表は手で書かず、**作り方をスクリプトにして**、出力を `data/config/` のファイル（例: `fictional_special_profile.json`）に置く（例: `scripts/build_fictional_special_profile.py`）。作り直せるようにするため。

1. 実在（2024〜2026年版の日本人）から、特能ごとに全体の保有率 `r_all`、区分ごとの保有率を出す。
2. 区分ごとの倍率を、人数で縮める: `m = 1 + w × (r_区分 / r_all − 1)`、`w = n / (n + 60)`（`n` はその区分の実在の人数）。野手は ポジションの倍率 × 打席の倍率。
3. 目標 = `水準 × 倍率`。生成の区分の人数の割合で平均したとき、水準と同じになるようにそろえる。
   - 水準は、ふつうは**生成の今の全体の保有率**（全体の水準は変えず、左右・ポジションの差だけ入れる）。
   - 次の特能だけは、水準も実在にする: 投手の対ランナー（青）、野手のお祭り男・春男・夏男・秋男・プレッシャーラン。
   - 赤の対ランナー×は、実在の投げ手ごとの保有率をそのまま目標にする。
4. 対象にする特能: 青特（マスターの `kind` が red・green・gold 以外）で、ランク特能・起用法でないもの。実在で10人以上が持つもの（上の水準を実在にする特能は除く）。`FICTIONAL_LINKED_SPECIALS` の特能と「実在にない特能」は除く。○○キラーは除く。
5. 「今の保有率 `c`」は、この段階の**前**の生成（球団生成300球団）で測る。
6. 一度流して、区分ごとの結果が目標からずれた分を、目標に足し戻して1回だけ直す（`t' = t + (t − 結果)`）。

## 2. 判定

### 2-1. 新しい判定（球団生成300球団、架空球団用の日本人）
PR #110 の仕組み（「実在」の判定、誤差つきの合否、id）で作り、`run_checks.py` に組み込む。新しいスクリプト（例: `scripts/check_special_profile.py`）か、`check_fictional_balance.py` に節を足す。

| 項目 | 合格の範囲 |
|---|---|
| 投手の青特の数 左・右 | 実在±0.25 |
| 投手の青特の左右差（左−右） | 実在（+0.76）±0.30 |
| 野手の青特の数 全体・左打・右打 | 実在±0.20 |
| 野手の青特の左右差（左打−右打） | 実在（+0.62）±0.25 |
| ポジションごとの青特の数 | 実在±0.30 |
| 投手の赤特の数 | 実在±0.10 |
| 右投手のクロスファイヤー | 0人 |
| 奪三振・内野安打○・広角打法の、帯 × 投打ごとの保有率 | 実在±0.08（人数が少ない帯は誤差つきで判定） |

- 実在の青特の数は○○キラーを数えない。
- 個別生成（架空球団用・投手と野手 各5000人）は参考として同じ表を出す。

### 2-2. 既存の判定の扱い
- `run_checks.py` を正式な規模で、全スクリプトを単独で流す。
- 特能・査定・戦力で「悪化」が出るのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけ `--update-snapshot --only ... --reason` で更新する。
- 動いてはいけない項目（能力・弾道・走力・変化球・ランク特能、外国人・ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定:
  - `check_age_profile.py` の年齢帯ごとの青特・赤特・緑特の数（1-7 の課題）。
  - `check_fictional_balance.py` の特能の出現率・能力との連動・特能数の分布。
  - `check_fielder_position.py` のポジションごとの査定（捕手が実在に近づくはず）。
  - `validate_team_mode.py` の戦力レベル (a)〜(f)、球団ごとの散らばり、背番号。
- 「固定」の基準値を更新する場合は `--update-baselines --only` で項目を絞り、理由を付ける。

### 2-3. 変わらないことの確認
- 助っ人外国人用・ドラフト候補用の投手と野手: seed 1〜1000 で完全に一致（マスターに足した4つが出ないこと）。
- 架空球団用の投手と野手: 名前・年齢・ポジション・投打・能力・弾道・変化球・ランク特能が、改修前と一致する。変わった項目を人数つきで一覧にする（特能が変わった人数、特能から決まる値があればそれも）。
- `tests/test_hash_independence.py` が通ること。全テストを流し切る。
- テストの期待値は、架空球団用と球団生成の分だけ、理由を書いて更新してよい。
