# 実在データの「対ランナー」の取り違え 修正指示

## 目的

実在データの「対ランナー」は**赤特（対ランナー×）**だが、取り込みで色が捨てられ、アプリの特能マスターでは**青特（対ランナー○）**として扱われている。そのため、実在の投手の青特の数・赤特の数・査定がずれている。実在データの読み方だけを直す。

**生成のしくみは変えない**（生成側の「対ランナー」「対ランナー×」の出し方は、次の改修「青特の型」で直す）。

**前提**: PR #115 をマージした後の main（81c0511）で作業する。

---

## 0. 調査の結果

### 0-1. 実在のHTMLでは赤特
実在のHTML（パワプロ 2022〜2026 のデフォルト選手データ）では、特能の色が `class` で分かれている（`P`＝青、`M`＝赤、`PM`＝青赤どちらにもなる特能）。

```html
<b class="P">奪三振</b><b class="PM st9">フライボールピッチャー</b><b class="PM">荒れ球</b><b class="M">対ランナー</b><b class="M">四球</b>
```

- 「対ランナー」は 2022〜2026 の全 113 件が `class="M"`（赤）。青のほうは「対ランナー○」という名前で載っている。
- ゲーム画面の査定の検証データ（`tests/rating_game_cases.py`）でも、瀧中投手（楽天）の赤特は「対ランナー×」と表示されている。
- 実在のHTMLの全特能を `class` とマスターの `kind` で照らし合わせたところ、食い違いはこの1件だけだった（シュート回転は 2022〜2023 だけの赤特で、マスターにないが、2024 年版以降は使っていない）。

### 0-2. アプリの名前
| | ゲーム・実在のHTML | アプリの特能マスター | 査定表（`rating_table.json`） |
|---|---|---|---|
| 青 | 対ランナー○ | 対ランナー（blue） | 対ランナー○ +6（`rating.py` で「対ランナー」→「対ランナー○」に読み替え） |
| 赤 | 対ランナー（class=M） | 対ランナー×（red） | 対ランナー× −5 |

`import_real_powerpro_players.py` は `class` を捨てて名前だけを残すので、実在の赤の「対ランナー」が、アプリでは青の「対ランナー」として扱われる。

### 0-3. 影響（2024〜2026年版の日本人投手）
| 項目 | 今の値 | 正しい値 |
|---|---|---|
| 赤の対ランナーの保有率 | 0%（青として数えている） | 左 8.4%・右 8.8% |
| 青の対ランナーの保有率 | 左 8.4%・右 8.8%（赤の分） | 左 1.7%・右 2.3%（対ランナー○） |
| 青特の数の平均 | 2.97 | 約2.88（−0.087） |
| 赤特の数の平均 | 0.87 | 約0.96（+0.087） |
| 査定 | 赤の対ランナーの投手に +6 | −5（1人あたり −11、投手全体の平均で約 −1） |

- `scrape_real_specials.py` の `ABILITY_NORMALIZATION = {"対ランナー○": "対ランナー"}` は、青の名前をアプリにそろえているが、赤と区別していない。

## 1. 修正の内容

### 1-1. 実在データの読み込み
- `scripts/import_real_powerpro_players.py` で特能を読むとき、`class` が `M` の「対ランナー」を「対ランナー×」として記録する。「対ランナー○」は「対ランナー」（アプリの青の名前）にする。
- 一般化はしなくてよい（食い違いはこの1件だけ）。名前の読み替えの表を1か所にまとめ、理由をコメントに書く。
- `scrape_real_specials.py` も同じ読み替えにする（使っている箇所があれば）。

### 1-2. 実在データの作り直し
- `scripts/build_real_team_reference.py` で、実在データ（`local_data/real_players_2022_2026.csv`、`data/reference/` の CSV、球団分析で使う実在の集計）を作り直す。
- 作り直す前と後で、変わった値の一覧を出す。想定は、投手の青特・赤特の数、査定、それに関わる球団の集計（投手力など）だけ。野手と、能力・変化球の値は変わらないこと。

### 1-3. 判定スクリプトの特能の一覧
- `scripts/check_age_profile.py` の赤特の一覧の「対ランナー」を「対ランナー×」にする（実在・生成とも同じ一覧で数えているため。今は生成の青の「対ランナー」を赤として数えている）。
- `scripts/check_fictional_balance.py` の「実在にない特能」の一覧から「対ランナー×」を外す（実在に 8.6% ある）。
- ほかのスクリプトにも同じ一覧があれば、同じように直す。

### 1-4. 変えないもの
- `app.py`（生成）と特能マスター。`app.py` の `FICTIONAL_AGE_NEGATIVE_SPECIALS` にも同じ「対ランナー」があるが、生成が変わるので次の改修で直す。
- `generator/rating.py` の読み替え（「対ランナー」→「対ランナー○」）。読み込みを直せば正しくなる。

## 2. 検証

### 2-1. 直ったことの確認
- 実在（2024〜2026年版の日本人投手）で、「対ランナー×」が 左 8.4%・右 8.8%、「対ランナー」が 左 1.7%・右 2.3% 前後になる。
- 青特・赤特の数の平均が 0-3 の「正しい値」に近くなる。
- `tests/rating_game_cases.py` の査定の検証が、今までどおり通る。

### 2-2. `run_checks.py`
- 正式な規模で流す（全9本、ほかの重い処理と並べない）。
- 実在の値が変わるので、「悪化」「改善」が出るのは想定内。**生成の値は変わっていない**ので、動いたのは実在側（比べる相手）だけのはず。一覧を出し、動いた理由が「実在の対ランナーの読み直し」で説明できるかを1件ずつ確かめる。
- 説明できる項目だけ `--update-snapshot --only ... --reason` で更新する。説明できない項目が出たら、更新せずに報告する。
- 新しく要注意・不合格になった項目（例: 生成に「対ランナー×」がないこと、投手の赤特の数）は、次の改修で直すので、今回は報告だけでよい（受け入れの記録には登録しない）。
- 「固定」の基準値を更新する場合は `--update-baselines --only ... --reason`。

### 2-3. 生成が変わらないこと
- 6区分（架空球団用・ドラフト候補用・助っ人外国人用 × 投手・野手）の seed 1〜1000 と、球団生成 seed 1〜50 が、修正前と完全に一致する。
- 全テストを流し切る。
