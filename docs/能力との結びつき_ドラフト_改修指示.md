# 能力との結びつき（ドラフト候補用）と持ち越し2件 改修指示

## 目的

3段階の4本目（最後）。PR #129〜#131 で入れた「能力に合った選手が持つ」仕組みを**ドラフト候補用**に入れる。あわせて、ドラフト候補のランク特能の形を直し、#131 から持ち越した2件を直す。

1. **ドラフト候補のランク特能の形**: 今は共通の処理で付けたランクがそのまま残っていて、A〜G がなだらかに広がっている（どのランク特能も A・G が1〜3%）。実在のプロ1年目は D に集まり、A・G はいない。投手の回復は E・F が6割（若手は回復が悪い）。
2. **ドラフト候補のランク特能と能力**: 回復・打たれ強さ（投手）、回復・送球・キャッチャー（野手）を能力で傾ける（#129 と同じ）。
3. **ドラフト候補の特能と能力**: 21特能を能力の合成値で付け替える（#130 と同じ）。
4. **持ち越し①（外国人の広角打法）**: 付けたい特能と同時に持てない特能を相手が持っていて、相手の r が付けたい特能の r より小さければ、相手を外して付ける。外国人の区分だけ。
5. **持ち越し②（日本人の奪三振の帯）**: 左投・球速152〜155の帯の保有率（0.438、範囲 0.474〜0.634）を、付け替え前の保有率（`FICTIONAL_LINKED_HAND_RATES` の奪三振の左投）を上げて戻す。

対象はドラフト候補用と、外国人の広角打法などの付け替え、日本人の奪三振。能力は変えない。

**前提**: PR #131 をマージした後の main（17a94b5）で作業する。

## 1. 改修の内容

### 1-1. ドラフト候補のランク特能を引き直す

| 回復 | 救援 | コントロール・スタミナ | 0.80 |

### 1-3. ドラフト候補の特能の付け替え
- `fictional_ability_special_link` をドラフト候補でも呼ぶ（`apply_draft_pitcher_balance`・`apply_draft_fielder_balance` の `draft_adjust_specials` のあと）。区分「ドラフト候補用」、特能数の上下限は `special_count_bounds("ドラフト候補用", …)`、副乱数の名前空間は新しく `draft_ability_special_link_v1`。
- 表の重み w は #130 の日本人と同じ。平均・SD はドラフト候補の生成の値（1-2 と同じ）。除く割合も日本人と同じ（野手 0.5、投手 0.75）。目標は日本人の実在（#130）。
- 対象は、ドラフト候補で保有率が3%以上の特能（投手12・野手9）。奪三振は日本人と同じく、重みは総変化量だけ・全体の強さを除かない・p に球速の帯ごとの保有率（p帯）。
- b・gain・区分ごとの p・ρ・M・SD・p帯 の試作の値は試作表の `ドラフト候補用`。p・ρ・M・SD・p帯 は PC の改修前の生成で測り直す。

### 1-4. 持ち越し①: 外国人の、同時に持てない特能の付け替え
- `fictional_ability_special_link` で、付けたい特能の r > 1 なのに、同じグループ・矛盾する特能を持っていて付けられないとき、**その相手の特能も表にあって、相手の r が付けたい特能の r より小さければ、相手を外して付ける**（#131 で試した案。広角打法の差 1.11→約1.40、保有率 18.6→約18.5%）。
- 表の区分ごとに入り切りできるようにし、**今は助っ人外国人用だけ**で使う。架空球団用の日本人・ドラフト候補用では使わない（日本人野手を変えないため）。
- 乱数の引く回数は変えない（付けるかどうかの乱数は今のまま1回）。

### 1-5. 持ち越し②: 日本人の奪三振（左投）
- `FICTIONAL_LINKED_HAND_RATES["投手"]["奪三振"]` の左投の帯を上げる。帯は 〜147／〜151／〜155／156〜。出発点の例（試作していない）:
  - `左|先発` [0.09, 0.15, 0.45, 0.70] → [0.09, 0.15, 0.56, 0.75]
  - `左|救援` [0.20, 0.40, 0.60, 0.80] → [0.20, 0.40, 0.72, 0.85]
- PR #119・#120 の奪三振の帯の判定（左投・球速152〜155 0.474〜0.634、156以上）が合格になるまで調整する。右投・ほかの帯は変えない。
- 変えたら、日本人の奪三振の付け替えの p帯（先発・救援ごとの帯の保有率）と M を測り直す（p帯 は付け替え前の帯の保有率なので）。
- この表は共有の乱数のコピーで引く計算だけで使う（空回しは投打の差なしの全体の保有率）ので、ランク特能・体重の乱数の並びは変わらない。

## 2. 判定

### 2-1. 新しい判定（ドラフト候補 投手・野手 各5000人）
`scripts/check_draft_balance.py` に節を足すか、`rank_ability.py`・`special_ability_link.py` にドラフト候補の節を足す。1年目の実在（0-1 の初登場の日本人）を `--build-real` で作る。誤差は異なる選手の数で出す。

| 項目 | 合格の範囲 |
|---|---|
| 1-2 の7区分の相関 | 日本人の実在±0.15（誤差つき） |
| ランク特能の割合（投手7・野手8、B〜F） | 1年目の実在±6ポイント（誤差つき） |
| ランク特能の A・G の割合 | 各 1.0%以下 |
| ランク点（投手・野手） | 1年目の実在±0.6（誤差つき） |
| 1-3 の21特能の差 | 日本人の実在±0.4（誤差つき） |
| 1-3 の21特能の保有率 | 改修前±1.5ポイント |

持ち越しの判定:
- 外国人の広角打法の差（#131 の判定）が合格になること。外国人の25特能の保有率が改修前（#131 の後）±2ポイントのまま。
- 日本人の奪三振の帯（PR #119・#120 の判定）がすべて合格になること。日本人の奪三振の差（#131 の判定、総変化量）が合格のまま。

### 2-2. 検証の進め方（PC の負荷を減らす）
- **PC で作業する**（1-4・1-5 は外国人・球団生成に関わるため）。
- 調整中は、ドラフト候補は `check_draft_balance.py` と新しい判定だけ（個別生成なので軽い）。1-4 は `check_foreign_balance.py` と `special_ability_link.py`、1-5 は奪三振の帯の判定（`check_special_profile.py` など）だけを流す（`--quick` でも可）。
- 値が決まったら、変えていない区分（架空球団用の日本人野手）が seed 1〜1000 と球団生成で改修前と完全に一致することを確かめる。
- 正式な規模の流しは1回（並列数2）。スナップショットは流し終えた結果から書き込む（PR #125〜#131 と同じやり方）。

### 2-3. 既存の判定の扱い
- ランク特能・特能・査定・戦力・背番号で値が動くのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけスナップショットを更新する。
- 動いてはいけない項目（能力、架空球団用の日本人野手、日本人投手のランク特能）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定: `check_draft_balance.py` の査定・特能の数・入団経路ごとの値（PR #110 以前からの判定。ランクを引き直すので査定が下がる）、`check_foreign_balance.py`、奪三振の帯、`validate_team_mode.py` の戦力・背番号。
- 判定の範囲は実在から決めたまま動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- ドラフト候補: 名前・年齢・ポジション・投打・能力・弾道・変化球・身長・体重が改修前と一致する。
- 架空球団用の日本人野手: 全項目一致（背番号を除く）。日本人投手: 奪三振に関わる特能・査定以外が一致。外国人: 能力など一致し、変わるのは特能（1-4）・査定。
- 変わった項目を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
