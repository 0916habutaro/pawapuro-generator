# 球団分析（チーム単位のバランス可視化・実在比較・出力） 改修指示

## 目的

「球団生成」で作った球団を**チーム単位**で分析する画面「球団分析」を追加する。

- 人数・能力・年齢などのバランスを、**球団ごと**に表と図で見られるようにする。
- **カテゴリ別**（年齢帯・ポジション・投手役割・外国人／日本人・投打など）に切り替えて見られるようにする。
- **実在球団（2022〜2026年版パワプロ、12球団×5年＝60チーム）と比較**できるようにする。実在60チームの分布の中で、生成球団がどこにいるかを示す。
- 分析結果を**Excel と CSV で出力**できるようにする。

**生成ロジックは一切変えない。** 今回は「見る・比べる・出す」だけを作る。`generate_team` / `generate_player` の結果が改修前と seed まで完全に同じであること。

#### zip の注意点（確認済み）
- zip 内のフォルダは `実在2022-2025/2022年版データ/` 〜 `2025年版データ/`。**年版はフォルダ名から決める**。ファイル名は当てにならない（2023年版フォルダのファイル名は「eBASEBALLパワフルプロ野球2022｜…」、2025年版フォルダは「パワフルプロ野球2024-2025｜…」）。
- 年版が違っても同じファイル名があるので、年版ごとに分けて処理する。
- zip のファイル名は cp932（UTF-8 フラグなし）。既存の `decode_zip_member_name()` で読める。
- 既存の取り込み処理 `scripts/import_real_powerpro_players.py` で、そのまま全件読めることを確認済み（年版ごとにフォルダへ展開して `--input-dir` に渡した結果）:

| 年版 | 選手数 | 投手 | 野手 | 球団数 | 取り込み失敗 |
|---|---|---|---|---|---|
| 2022 | 833 | 421 | 412 | 12 | 0 |
| 2023 | 820 | 411 | 409 | 12 | 0 |
| 2024 | 828 | 421 | 407 | 12 | 0 |
| 2025 | 834 | 425 | 409 | 12 | 0 |
| 2026 | 791 | 402 | 389 | 12 | （既存） |

  取り込み処理自体は**変更しない**。zip を一時フォルダに年版別に展開して既存の関数（`read_sources` → `parse_*` → `combine_results`）を呼ぶ。

#### 年齢・外国人の扱い（重要）
- **年齢は HTML に無い**。年齢が分かるのは 2026年版（entry_route xlsx）と、外国人一覧の外国人だけ。
  - 2026年版の名簿から逆算（`年齢2026 −（2026 − 年版）`）すると、球団＋名前で一致する割合は 2022: 38%、2023: 49%、2024: 60%、2025: 76% しかなく、しかも「2026年まで残った選手」に偏る（若手が多く残る）。
  - よって**年齢・年齢帯・プロ年数・入団経路に関する比較は 2026年版の12球団だけを基準にする**。画面と出力には「年齢系の基準は2026年版12球団」と明記する。
  - 逆算の年齢は `age_backcalc` 列として選手データに残してよいが、比較の基準には使わない。
- **外国人の判定**:
  - 2022・2024・2025年版: 外国人一覧（`combined_2022_2025_complete`）と球団（略称→正式名の対応表を作る）＋登録名で照合する。
  - 2023年版と、一覧で照合できなかった選手: 既存の `real_team_composition_2022_2026.csv` と同じ「登録名がカタカナのみ」で判定する。
  - 2026年版: `entry_route == "海外・その他"` かつ登録名がカタカナのみ。
  - 判定した外国人数を `real_team_composition_2022_2026.csv` の `foreign` 列と球団ごとに比べ、差がある球団を検証レポートに出す（差があってもエラーにしない。外国人数は目安）。
- 2026年版は総数が他年より少ない（シーズン前の名簿）。人数系の比較では年版を選べるようにする（下記2-3）。

## 2. 分析の定義（`generator/team_analysis.py` 新規・Streamlit 非依存）

### 2-1. 選手の正規化フレーム

生成選手（dict）と実在選手（CSV行）を、同じ列の `DataFrame` にする。以降の集計はすべてこのフレームに対して行う。

| 列 | 生成選手の出どころ | 実在選手の出どころ |
|---|---|---|
| `team_key` | 生成: `gen:{team_id}`（未保存は `gen:unsaved`） | `real:{season}:{team}` |
| `team_label` | 球団名 | `2025 阪神タイガース` の形 |
| `name`, `uniform_number`（文字列） | そのまま | `number` を文字列に |
| `role`（投手／野手） | `role` | `role` |
| `position`（捕手〜外野手、投手は「投手」） | メインポジション | `main_position` |
| `pitcher_role`（先発／救援） | `primary_pitcher_role()` が「先発」なら先発、「中継ぎ」「抑え」は救援 | `pitcher_roles` の先頭が「先」なら先発、それ以外は救援 |
| `throws`（右／左）、`bats`（右／左／両） | `batting_throwing` | `throws_bats` |
| `is_foreign`（bool） | `roster_origin == "foreign_import"` | 1-1 の判定 |
| `age`, `pro_years`, `entry_route` | そのまま | 2026年版のみ。他年は欠損 |
| 能力（投手）`球速, コントロール, スタミナ, 変化球数, 総変化量` | abilities / breaking_balls | `top_speed` 等 / breaking_balls |
| 能力（野手）`弾道, ミート, パワー, 走力, 肩力, 守備力, 捕球` | abilities | `trajectory` 等 |
| `rating` | `player_rating()` | `player_rating(real_player_to_rating_dict(row))` |
| `n_blue, n_red, n_gold, n_green, rank_points` | 特殊能力の分類（既存の分類関数を使う） | 同左（`special_abilities` シート/CSV） |
| `player_class`, `archetype` | 内部分類 | 欠損（生成のみの軸） |

- 変化球数・総変化量の数え方は既存の比較処理（`compare_real_and_generated_balance.py` の `normal_pitch_count_primary_only` / `total_movement_primary_only`）と同じにする。
- 保存済み球団は `players.team_id` で読み出し、**既存の「DB行→選手dict」変換**（履歴・バランス確認で使っているもの）を通してから正規化する。新しい変換を書かない。

### 2-2. カテゴリ軸（`axis`）

| axis | group の値 | 実在比較 | 備考 |
|---|---|---|---|
| `全体` | 全体 | 2022〜2026 | |
| `投手/野手` | 投手, 野手 | 2022〜2026 | |
| `ポジション` | 投手, 捕手, 一塁手, 二塁手, 三塁手, 遊撃手, 外野手 | 2022〜2026 | 野手はメインポジション |
| `投手役割` | 先発, 救援 | 2022〜2026 | 実在に「抑」が先頭の投手はいないため、中継ぎと抑えは**救援にまとめる** |
| `年齢帯` | `AGE_BAND_LABELS` の5区分 | **2026のみ** | `AGE_BANDS` を再利用 |
| `外国人` | 日本人, 外国人 | 2022〜2026 | |
| `投打` | 右投, 左投 ／ 右打, 左打, 両打 | 2022〜2026 | 投手は投げ、野手は打席で分ける（投手=投げ手、野手=打席） |
| `プロ年数` | 1年目, 2〜3年, 4〜6年, 7〜9年, 10年以上 | **2026のみ** | |

| `査定帯` | 上位10%, 10〜25%, 25〜50%, 下位50% | 2022〜2026 | 区切りは**実在全選手（役割別）の査定の分位点**で固定し、生成にも同じ境界を使う |
| `選手格` / `型` | 内部分類 | **なし**（生成のみ） | 表示は折りたたみの中だけ |
| `年齢帯×ポジション` | 交差 | 2026のみ | ヒートマップ用。集計ファイルにも入れる |

### 2-3. 指標（`metric`）

各 axis×group について次を出す。

| metric | 内容 |
|---|---|
| `人数` / `構成比` | 人数と、球団内（その役割内）の割合 |
| `平均年齢` | 年齢系の基準は 2026 のみ |
| 能力の平均 | 投手5項目・野手7項目（2-1） |
| `査定_平均` / `査定_最大` | |
| `特能_青` / `特能_赤` / `特能_金` / `特能_緑` / `ランク特能点` | 1人あたり平均 |

球団全体の**主要指標**（概要に出す。`team_rating_metrics` と同じ定義を使う）:

| 主要指標 | 定義 |
|---|---|
| 総合力 | 査定の上位28人平均 |
| 投手力 | 投手の査定の上位13人平均 |
| 野手力 | 野手の査定の上位15人平均 |
| 全員平均 | 査定の全員平均 |
| 平均年齢／主力の平均年齢 | 全員／査定上位28人（2026基準） |
| 外国人数、左投手数 | |
| 先発の厚み | 先発の査定上位6人平均 |
| 救援の厚み | 救援の査定上位7人平均 |

**デプス（戦力の厚み）**: ポジションごとに査定順で並べた「1番手・2番手・3番手」の査定（外野手は1〜5番手、捕手は1〜3番手、内野は1〜2番手、先発1〜6番手、救援1〜7番手）。サブポジションは数えない（メインポジションのみ）。

### 2-4. 実在との比較方法

- 基準集団: 選んだ年版（既定は 2022〜2026 の全部＝60チーム）の球団ごとの値。年齢系の指標は年版の選択に関わらず 2026（12チーム）。
- 各指標について次を出す:
  - 実在の `最小 / 10% / 中央 / 90% / 最大 / 平均`
  - 生成球団の値と、**実在の中での百分位**（0〜100。同値は中間順位）
  - 判定: 実在の最小〜最大の外＝「範囲外」、10〜90%の外＝「やや外れ」、それ以外＝「範囲内」
  - 実在平均との差（値と％）
- **特定の実在球団と1対1で比較**も選べる（例: 2025 阪神タイガース）。差の列を出す。
- 実在の選手単位データがあるときだけ、能力の**分布**（箱ひげ）も比べる。
- 判定の色は既存の「構成チェック」と同じ目立たない警告色（範囲外＝赤系、やや外れ＝黄系）。色だけで伝えず「範囲外」等の文字も出す。

## 3. 画面「球団分析」

`main()` の `pages` に追加: `st.Page(team_analysis_page, title="球団分析", icon="📈", url_path="team-analysis")`。順番は「選手生成」→「球団生成」→「球団分析」→「バランス確認」。

「球団生成」の結果画面（概要の下、保存・出力ボタンの並び）に **「この球団を分析」** ボタンを追加し、`st.switch_page` で球団分析へ移る。未保存の球団もそのまま分析できること（`st.session_state` の球団を使う）。

### 3-1. サイドバー

- **分析する球団**（multiselect、最大12球団）
  - 「生成中の球団（未保存）」… 球団生成画面に結果があるときだけ出す
  - 保存済み球団: `ID n：球団名（戦力レベル・チームカラー・作成日）`。新しい順。
- **実在の比較基準**
  - 年版（multiselect、既定は 2022〜2026 全部）
  - 実在球団と1対1で比べる（selectbox、任意。「なし」が既定）
- 保存済み球団が0件で未保存の球団も無い場合は、本文に「球団生成で球団を作ると、ここで分析できます」と出す。

### 3-2. タブ

1つの球団を選んでいるときと、複数のときで内容を変える。

1. **概要**
   - 主要指標を `st.metric` で並べ、各値の下に「実在の百分位 n」と判定を小さく出す。
   - **実在分布の中の位置**: 主要指標ごとに横1列のドットプロット（実在60チーム＝灰色の点、生成球団＝強調色の大きい点、10〜90%の範囲を薄い帯）。
   - 投手力×野手力の散布図（実在60チーム＋生成球団）。
   - 範囲外・やや外れの項目の一覧（「どこが実在とずれているか」をすぐ分かるように）。
2. **人数構成**
   - 既存の構成チェック表（`team_composition_frame`）を流用し、百分位列を足す。
   - カテゴリ軸を選ぶ（`st.segmented_control`、既定はポジション）→ 生成の人数と実在の中央値・10〜90%を並べた横棒。
3. **能力**
   - カテゴリ軸 × 指標を選ぶ。表は「group × 指標」で、生成値・実在中央・実在10〜90%・判定。
   - 図: group ごとに実在の10〜90%の帯＋中央の線＋生成の点。
   - 実在の選手単位データがあれば、選んだ能力の箱ひげ（実在の全選手 vs 生成球団の選手）。
4. **年齢**（基準は2026年版12球団と明記）
   - 年齢別の人数ヒストグラム（1歳刻み。実在12球団の平均人数を線で重ねる）。
   - 年齢帯×ポジションの人数ヒートマップ（生成）と、実在平均との差。
   - 年齢帯ごとの平均査定。
5. **戦力の厚み**
   - 2-3 のデプス表（ポジション×何番手、セルは査定と選手名）。実在の同じ枠の10〜90%から外れたセルに色。
   - 「手薄なポジション」「層が厚すぎるポジション」を文章で一覧。
6. **特殊能力**
   - 役割・カテゴリ別の青／赤／金／緑の1人あたり個数と、ランク特能点。実在との比較列。
7. **選手一覧**
   - 正規化フレームを表で出す。カテゴリ（年齢帯・ポジションなど）で絞り込める。行を選ぶと既存の能力カード（`render_detail_panel`）を表示。
8. **球団比較**（2球団以上を選んだときだけ出す）
   - 主要指標を球団ごとに並べた表（列＝球団、最後に実在の中央・10〜90%）。
   - 主要指標の球団別横棒、投手力×野手力の散布図（全選択球団＋実在）。
   - カテゴリ軸を選んで、人数・平均能力を球団別に並べる。

### 3-3. 見た目

- グラフは Altair。既存の `balance_bar_chart` と `UI_COLORS` に合わせる。
- 色は「生成＝強調色1色」「実在＝灰色」で固定し、複数球団のときだけ球団ごとの色（既存パレット）を使う。凡例を必ず付ける。
- 実在の比較基準（年版、何チーム、年齢系は2026のみ）を各タブの上に1行で出す。
- ラベル・説明文はすべて日本語。

### 3-4. 性能

- 実在の集計・選手データ、カテゴリ境界は `st.cache_data` / `lru_cache` で一度だけ読む。
- 保存済み球団の正規化フレームは `team_id` をキーにキャッシュする（球団を保存・削除したらクリア）。
- 12球団選択時でも、タブ切り替えが Windows で2秒程度に収まること。計測して報告する。

## 4. 出力

画面上部（サイドバーではなく本文の最上部）に「Excelで出力」「CSV（zip）で出力」を置く。**表示中の条件**（選んだ球団、実在の年版、1対1の比較相手）の結果を出す。未保存の球団も出力できる。

### 4-1. Excel（`球団分析_{球団名 or 複数球団}_{日時}.xlsx`、`export_file_name` に合わせる）

| シート | 内容 |
|---|---|
| `設定` | 出力日時、アプリのバージョン、分析した球団（ID・名前・seed・戦力レベル・カラー）、実在の基準（年版・チーム数、年齢系は2026のみ）、1対1の比較相手 |
| `概要` | 主要指標 × 球団（＋実在の最小・10%・中央・90%・最大・百分位・判定） |
| `実在比較` | 全 axis×group×metric の比較（縦持ち。フィルタしやすい形） |
| `人数構成` | 構成チェック表＋カテゴリ別人数 |
| `カテゴリ別能力` | axis×group×能力の平均（生成と実在） |
| `年齢` | 年齢別人数、年齢帯×ポジション |
| `戦力の厚み` | デプス表 |
| `特殊能力` | 特能の個数の比較 |
| `選手一覧` | 正規化フレーム（`team_label` 列付き。背番号は文字列で "00" を保持） |
| `実在基準` | 比較に使った実在の集計値（年版×球団） |

- 見出し行の固定、列幅の調整、判定列の色（範囲外・やや外れ）を openpyxl で付ける。
- `概要` と `人数構成` には openpyxl のネイティブのグラフ（横棒）を入れる（画像ではなく Excel のグラフ。オフラインで開ける）。
- 複数球団のときは1つのブックにまとめ、各シートに `team_label` 列を持たせる。

### 4-2. CSV（zip）

- 上の各シートを1つずつ CSV にして zip にまとめる（UTF-8 BOM。既存の CSV 出力と同じ）。ファイル名は `01_概要.csv` のように番号付き。

### 4-3. やらない出力

PDF、グラフの画像（PNG）出力、HTML レポートは今回は作らない（追加の外部ライブラリが要るため）。

## 6. 検証

### 6-1. 構築スクリプトの確認
- 年版ごとの選手数が 1-1 の表と一致する。
- 人数構成CSVとの整合チェックの結果（不一致0件が目標）。
- 外国人数の差の一覧。
- 実在60チームの主要指標の分布（最小・10%・中央・90%・最大）を summary.md に出す。参考までに、取り込み結果から計算した**球団平均の能力**（60チーム）は次の通り。これと大きく違ったら取り込みか正規化の誤り:

| 投手 コントロール | 45.9 | 48.8 | 50.8 | 53.2 | 55.2 |
| 投手 スタミナ | 50.0 | 50.9 | 51.9 | 53.7 | 55.9 |
| 野手 弾道 | 2.3 | 2.5 | 2.6 | 2.7 | 2.9 |
| 野手 ミート | 33.8 | 35.3 | 41.1 | 43.5 | 45.6 |

### 6-2. テスト `tests/test_team_analysis.py`
- 生成球団（固定 seed）と実在選手（小さなフィクスチャ）から作った正規化フレームの列が一致する。
- 各 axis の group の人数の合計が、その球団の総数（または役割の人数）と一致する。
- `team_headline` の総合力・投手力・野手力が `team_rating_metrics` と一致する。
- 百分位と判定: 作った分布（例: 1〜100）に対して、境界値（最小・10%・90%・最大ちょうど）の判定が仕様どおり。
- **実在球団を「生成球団」として入れたとき**、その球団自身との1対1比較の差がすべて0、実在分布の中の百分位が集計ファイルから計算した値と一致する。
- Excel: すべてのシートがあり、`選手一覧` の背番号 "00" が文字列のまま残る。CSV zip のファイル数とファイル名。
- 未保存の球団（session の dict）と、保存して読み戻した球団で、分析結果が一致する。
- 実在の選手単位ファイルが無い場合でも、集計ファイルだけで比較が動く。
- **生成結果が変わっていない**: 既存の `tests/test_team_mode.py` を含む全テストが通る。
