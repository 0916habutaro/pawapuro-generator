# 野手のランク点の年齢の傾き 測り直し 改修指示

## 目的

PR #124 で、走力・肩力の低い野手のランク（盗塁・送球・走塁）を下げなくした。その結果、年齢の高い野手のランク点が上がりすぎ、`check_age_profile.py` の「ランク点：各年齢帯が目標±2.0」が要注意になった（1.52 → 2.03）。

年齢でランクを傾ける補正（`FICTIONAL_AGE_RANK_BETA["野手"]`）は、PR #113 より前の、遅い選手を強く下げていた頃に合わせて決めたもの。今の状態に合わせて測り直す。

対象は架空球団用の日本人野手（個別生成・球団生成の両方）。投手、外国人、ドラフト候補用は変えない。

**前提**: PR #124 をマージした後の main（d00969c）で作業する。

## 0. 調査の結果

球団生成300球団（seed 1〜300、`PYTHONHASHSEED=0`）の日本人野手の、年齢帯ごとのランク点の平均。目標は `check_age_profile.py` の `TARGETS["野手"]["rk_pts"]`（実在2026年版を平滑化した値）。

## 1. 改修の内容

### 1-1. `FICTIONAL_AGE_RANK_BETA["野手"]` を変える
```
今:   (20, −0.13), (23.5, −0.06), (27.5, 0.015), (31.5, 0.085), (36, 0.05)
```

- `FICTIONAL_AGE_RANK_GAMMA["野手"]`（幅）は変えない。
- 重みを変えるだけで、乱数を引く回数は変えない。

### 1-2. 試作した結果（出発点）

container の作業コピーで試作した（球団生成300球団、`PYTHONHASHSEED=0`）。**この値を出発点にして、2章の判定で微調整する**。

|---|---|---|---|---|---|---|---|

- 年齢帯ごとのランク点の標準偏差（5.8／6.9／7.7／7.6／7.4）は、今とほとんど変わらない。
- ランク点の合計の打席の差: 左打 −0.87（実在 −0.68）、右打 +0.68（+0.64）。PR #123 の判定（実在±0.6）の中。
- 日本人野手の査定 251.5 → 251.3、捕手の査定 223.0 → 222.6（実在 222.7）、球団の野手力の中央 304.2 → 304.2。

試作で気づいたこと:
- 年齢との相関が 0.277 → 0.220 に下がり、範囲（0.20〜0.40）の下限に近づく。実在は 0.251。下限を割るようなら、〜21歳の傾き（−0.16）を少し弱めるか、30〜33歳（0.055）を少し強めて、年齢帯のずれ（±2.0）の中で相関を上げる。
- 別のβを試したとき（−0.17／−0.04／0.0／0.05／0.02）は、全体が −0.34 まで下がった。全体の水準は、PR #124 の「ランク点の合計（全体）実在±0.4」の判定にも効くので、両方を見て決める。

## 2. 判定

### 2-1. 対象の判定
新しい判定は作らない。次の既存の判定がすべて合格になること（範囲は今のまま）。
- `check_age_profile.py` の野手のランク点: 各年齢帯が目標±2.0（球団・個別とも）、年齢との相関 0.20〜0.40、SD の判定。
- `check_fielder_speed.py` の、PR #124 で足したランク点の判定（走塁・盗塁・送球の帯ごと、全体、ランク点の合計 全体・左打・右打）。
- `check_fielder_batting.py`・`check_fielder_position.py` の、PR #123 で足したランク特能の判定。

### 2-2. 検証の進め方（PC の負荷を減らす）
- 調整中は `check_age_profile.py` と `check_fielder_speed.py` だけを流す（`--quick` でも可）。`run_checks.py` 全体は流さない。
- 値が決まったら、変えていない区分（個別生成の架空球団用の投手、ドラフト候補用・助っ人外国人用の投手と野手）が seed 1〜1000 で改修前と完全に一致することを確かめる。
- 一致したら、それらの区分だけを使う判定（`check_draft_balance.py`、`check_foreign_balance.py`、`check_pitcher_control.py`、`check_pitcher_rank_pitches.py` など）は流さず、スナップショットもそのままにする。どれを省いたかを報告する。
- 正式な規模で流すのは、架空球団用の野手か球団生成を使う判定だけ。1回だけ流し、スナップショットを更新した後の確認は、更新した項目の値がスナップショットと一致することの確認で済ませる。
- 並列数を指定できるなら、PC を使いながら流せる程度に下げる。

### 2-3. 既存の判定の扱い
- ランク特能・査定・戦力・背番号で値が動くのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけ `--update-snapshot --only ... --reason` で更新する。
- 動いてはいけない項目（野手の能力・特能、投手、外国人、ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 判定の範囲は動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- 架空球団用の野手: 名前・年齢・ポジション・投打・能力・弾道・特能・身長・体重が改修前と一致する。変わった項目（ランク特能、査定）を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
