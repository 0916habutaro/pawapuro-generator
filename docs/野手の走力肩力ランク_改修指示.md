# 野手の走塁・盗塁・送球のランク（走力・肩力との連動） 改修指示

## 目的

架空球団用の日本人野手の、走塁・盗塁・送球のランク特能と、走力・肩力との結びつき方を実在に合わせる。

- 生成は、**走力・肩力が低い選手のランクを強く下げすぎ**ている（走力50未満の盗塁 生成 −2.16、実在 +0.06。肩力55未満の送球 生成 −1.29、実在 −0.29）。実在は、遅い選手・肩の弱い選手でも D のことが多い。
- 一方で、**走力70〜79の走塁が足りない**（生成 1.41、実在 2.37）。実在は走力70を超えると走塁がはっきり良くなる。

対象は架空球団用の日本人野手（個別生成・球団生成の両方）。投手、外国人、ドラフト候補用、能力・特能、ほかのランク特能は変えない。

**前提**: PR #123 をマージした後の main（62bd460）で作業する。PR #123 の完了報告で残った「ランク点の合計が左右とも実在より約0.4低い」件の続き。

---

## 0. 調査の結果

球団生成300球団（seed 1〜300、`PYTHONHASHSEED=0`、main 62bd460）の日本人野手と、実在（2024〜2026年版の日本人野手）を比べた。ランク点は査定表の点（D=0）。

### 0-1. 走力・肩力の帯ごとのランク点

| 走塁（走力） | 〜49 | 50〜59 | 60〜69 | 70〜79 | 80〜 |
|---|---|---|---|---|---|
| 生成 | 0.28 | 1.30 | 1.31 | 1.41 | 2.60 |
| 実在 | 0.51 | 0.79 | 0.98 | 2.37 | 3.17 |

| 盗塁（走力） | 〜49 | 50〜59 | 60〜69 | 70〜79 | 80〜 |
|---|---|---|---|---|---|
| 生成 | −2.16 | −0.44 | −0.34 | −0.18 | 1.82 |
| 実在 | +0.06 | −0.46 | −0.66 | −0.91 | +0.96 |

| 送球（肩力） | 〜54 | 55〜64 | 65〜74 | 75〜79 | 80〜 |
|---|---|---|---|---|---|
| 生成 | −1.29 | −0.45 | −0.43 | −0.34 | 0.57 |
| 実在 | −0.29 | −0.01 | −0.50 | −0.08 | 0.55 |

（実在の人数は帯ごとに120〜390人。）

- 原因: `apply_fictional_fielder_balance` の `link_shift` が、走力50以下・肩力55以下で 40〜50% の確率でランクを1段下げている。走力70〜79には何もしていない。
- その結果、遅い選手の多い捕手・一塁手の盗塁が低すぎる（捕手 生成 −1.14・実在 −0.15、一塁手 −1.35・−0.52）。

### 0-2. ランク点の合計

| | 生成 | 実在 |
|---|---|---|
| 日本人野手の全体 | −0.22 | −0.04 |
| 左打／右打 | −0.93／+0.38 | −0.68／+0.64 |

## 1. 改修の内容（`apply_fictional_fielder_balance` の `link_shift` と、重み）

### 1-1. `link_shift` の確率
- 走塁: 走力80以上で1段上げる確率 0.5 → 0.6。走力50以下で1段下げる確率 0.4 → 0.3。
- 盗塁: 走力80以上で上げる確率 0.6 → 0.45。走力50以下で下げる確率 0.5 → 0。
- 送球: 肩力55以下で下げる確率 0.4 → 0.1（肩力80以上は今のまま）。
- **乱数の引く回数を変えないため、条件（走力80以上・50以下、肩力80以上・55以下）はそのままにし、確率だけ変える**（確率0でも、今と同じく1回引く）。

### 1-2. 走力70〜79の走塁
- 走力70〜79で、確率 0.35 で走塁を1段上げる。
- この乱数は**新しい名前空間の副乱数**（例: `make_sub_rng(seed, "fictional_fielder_rank_link_v1")`）から引く。今の乱数の並びを変えないため。

### 1-3. 重み
`FICTIONAL_FIELDER_RANKED_WEIGHTS` の次の2つを変える（A／B／C／D／E／F／G）。
```
盗塁  0.3／3／11.7／57／23／5.5／0.2  （今は 0.3／3／11.7／62／18／4.8／0.2）
走塁  1.0／7／28／61／2.5／0.4／0.1  （今は 1.0／10／32／55／1.6／0.3／0.1。未検証の出発点、1-4 参照）
```

### 1-4. 試作した結果（出発点）

container の作業コピーで、1-1・1-2 と盗塁の重みを試作した（球団生成300球団、`PYTHONHASHSEED=0`）。走塁の重みは、試作の結果を見て決めた値で、まだ流していない。**この値を出発点にして、2章の判定で微調整する**。

試作で残った課題（正式版で調整する）:
- **走塁の走力50〜69が高い**（生成 1.3、実在 0.8〜1.0）。全体の走塁も +0.12 高い。走塁の重みの B・C を減らして D を増やす（1-3 の値）。走力80以上（生成 2.85、実在 3.17）が足りなくなるなら、走力80以上で上げる確率を上げる。
- 盗塁の走力70〜79（生成 −0.40、実在 −0.91）が高い。実在は、走力70〜79で盗塁が低く、80以上で一気に上がる形。直しきれなければ報告する。

## 2. 判定

### 2-1. 新しい判定（球団生成300球団、架空球団用の日本人野手）
PR #110 の仕組み（「実在」の判定、誤差つきの合否、id）で作り、`run_checks.py` に組み込む。`scripts/check_fielder_speed.py`（走力）に節を足す。

| 項目 | 合格の範囲 |
|---|---|
| 走塁・盗塁のランク点（走力の帯ごと、0-1 の5帯） | 実在±0.5（誤差つき） |
| 送球のランク点（肩力の帯ごと、0-1 の5帯） | 実在±0.5（誤差つき） |
| 走塁・盗塁・送球のランク点（全体） | 実在±0.2 |
| ランク点の合計（全体、左打、右打） | 実在±0.4 |

- 個別生成（架空球団用・野手5000人）は参考として同じ表を出す。

### 2-2. 検証の進め方（PC の負荷を減らす）
- 調整中は `check_fielder_speed.py` だけを流す（`--quick` でも可）。`run_checks.py` 全体は流さない。
- 値が決まったら、変えていない区分（個別生成の架空球団用の投手、ドラフト候補用・助っ人外国人用の投手と野手）が seed 1〜1000 で改修前と完全に一致することを確かめる。
- 一致したら、それらの区分だけを使う判定（`check_draft_balance.py`、`check_foreign_balance.py`、`check_pitcher_control.py`、`check_pitcher_rank_pitches.py` など）は流さず、スナップショットもそのままにする。どれを省いたかを報告する。
- 正式な規模で流すのは、架空球団用の野手か球団生成を使う判定だけ。1回だけ流し、スナップショットを更新した後の確認は、更新した項目の値がスナップショットと一致することの確認で済ませる。
- 並列数を指定できるなら、PC を使いながら流せる程度に下げる。

### 2-3. 既存の判定の扱い
- ランク特能・査定・戦力・背番号で「悪化」が出るのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけ `--update-snapshot --only ... --reason` で更新する。
- 動いてはいけない項目（野手の能力・特能、投手、外国人、ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定: PR #123 の対左投手・キャッチャーの判定（そのまま合格すること）、`check_age_profile.py` の野手のランク点の年齢帯、`check_fictional_balance.py` のランク特能の分布、`check_fielder_position.py` のポジションごとの査定、`validate_team_mode.py` の戦力レベル・散らばり・背番号・機動力カラー。
- 判定の範囲は実在から決めたまま動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- 架空球団用の野手: 名前・年齢・ポジション・投打・能力・弾道・特能・身長・体重が改修前と一致する（乱数の引く回数を変えていないため）。変わった項目（ランク特能、査定）を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
