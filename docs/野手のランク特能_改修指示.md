# 野手のランク特能（対左投手の打席差・捕手のキャッチャー） 改修指示

## 目的

架空球団用の日本人野手のランク特能を、実在に合わせる。

1. **対左投手を打席で分ける**: 実在は、左打者が左投手に弱く、右打者は強い。生成は左右で同じ。
2. **捕手のキャッチャーのランクを散らす**: 実在の捕手は E・F が46%いるが、生成は D に80%が集まっている。捕手の査定が実在より高い一因。

対象は架空球団用の日本人野手（個別生成・球団生成の両方）。投手、外国人、ドラフト候補用、能力・特能は変えない。

**前提**: PR #122 をマージした後の main（1e6eda4）で作業する。洗い出し（`docs/洗い出し結果_2026-10-10.md`）の候補1。

---

## 0. 調査の結果

球団生成300球団（seed 1〜300、`PYTHONHASHSEED=0`）の日本人野手と、実在（2024〜2026年版の日本人野手）を比べた。ランク点は査定表の点（D=0）。

### 0-1. 対左投手（ランクの割合 A／B／C／D／E／F／G、%）

| | 生成 | 実在 |
|---|---|---|
| 左打（実在523人） | 0.2／6.9／17.3／48.5／21.0／6.1／0.1 | 0／0.8／11.1／45.7／31.2／11.3／0 |
| 右打（実在566人） | 0.1／6.2／17.6／48.5／21.6／5.8／0.2 | 0／8.0／25.8／50.2／14.3／1.8／0 |

- 対左投手のランク点: 左打 生成 −0.08・実在 −1.54、右打 生成 −0.13・実在 +0.89。
- 野手のランク点の合計の打席の差（左打 生成 +0.71・実在 −0.68、右打 −0.21・+0.64）は、ほぼこれで説明できる。
- 原因: `FICTIONAL_FIELDER_RANKED_WEIGHTS["対左投手"]` が打席で分かれていない。投手の対左打者は投げ手で分けている（`"対左打者_左投"`）。

### 0-2. 捕手のキャッチャー（ランクの割合 A〜G、%）

| | 割合 | ランク点 |
|---|---|---|
| 生成 | 0.2／0.9／5.9／80.0／11.2／1.7／0.1 | −0.26 |
| 実在（2024〜26） | 0／1.6／8.6／43.9／31.6／14.3／0 | −1.81 |
| 実在 2024／2025／2026 | E+F 48%／46%／43% | |

- 年版によらず同じ傾向。
- 原因: `FICTIONAL_FIELDER_RANKED_WEIGHTS["キャッチャー"]` の D が 88 で、ほかが小さい。サブポジに捕手を持つ野手も同じ重みを使っている。

## 1. 改修の内容

### 1-1. 重みを足す
`FICTIONAL_FIELDER_RANKED_WEIGHTS` に、次の重みを足す（A／B／C／D／E／F／G）。今の重みは比 (実在 ÷ 生成) を掛けて作った。
```
対左投手_左打      0.1／0.6／11.3／46.2／32.7／10.7／0.2
対左投手_右打      0.4／6.5／25.8／50.7／14.6／1.8／0.1
キャッチャー_捕手  0.1／0.9／3.2／41.4／25.6／13.8／0.1
```
- 今の「対左投手」「キャッチャー」の重みは残す。両打の対左投手と、サブポジが捕手の野手のキャッチャーは、今の重みのまま。

### 1-2. 重みの選び方
- `apply_fictional_fielder_balance` で `fictional_ranked_specials` を呼ぶところに、`weights_key` を渡す（投手の `"対左打者_左投"` と同じやり方）。
  - 対左投手: 左打なら `"対左投手_左打"`、右打なら `"対左投手_右打"`、両打は `"対左投手"`。
  - キャッチャー: メインのポジションが捕手なら `"キャッチャー_捕手"`、それ以外は `"キャッチャー"`。
- 重みを変えるだけで、乱数を引く回数は変えない。

### 1-3. 試作した結果（出発点）

container の作業コピーで試作した（球団生成300球団、`PYTHONHASHSEED=0`）。キャッチャー_捕手 は、試作のあと結果を見て1回直した値を1-1に載せている（試作は C 2.0・D 48.3・E 24・F 11.8 で、C が少なく D が多めだった）。**この値を出発点にして、2章の判定で微調整する**。

| 項目 | 実在 | 改修前 | 試作 |
|---|---|---|---|
| 対左投手 左打（A〜G %） | 0／0.8／11.1／45.7／31.2／11.3／0 | 0.2／6.9／17.3／48.5／21.0／6.1／0.1 | 0／1.6／12.7／44.5／31.1／10.0／0.1 |
| 対左投手 右打（A〜G %） | 0／8.0／25.8／50.2／14.3／1.8／0 | 0.1／6.2／17.6／48.5／21.6／5.8／0.2 | 0.1／8.1／24.1／49.7／15.9／2.0／0.1 |
| 対左投手のランク点 左打／右打 | −1.54／+0.89 | −0.08／−0.13 | −1.33／+0.76 |
| ランク点の合計 左打／右打 | −0.68／+0.64 | +0.71／−0.21 | −0.75／+0.26 |
| 捕手のキャッチャー（A〜G %） | 0／1.6／8.6／43.9／31.6／14.3／0 | 0.2／0.9／5.9／80.0／11.2／1.7／0.1 | 0.2／1.4／5.3／51.2／29.6／12.2／0.1 |
| 捕手のキャッチャーのランク点 | −1.81 | −0.26 | −1.72 |
| 捕手の査定 | 222.7 | 223.4 | 222.2 |
| 日本人野手の査定 | 252.5 | 251.5 | 251.1 |
| 球団の野手力（上位15人）中央 | 302.2 | 304.6 | 304.4 |

試作で気づいたこと（今回は直さない。4章）:
- 捕手の盗塁のランク点（生成 −1.14、実在 −0.15）と走塁（+0.95、+0.36）、一塁手の盗塁・走塁がずれている。走力と連動させている部分（`link_shift`）が効いている。今回の改修の後に測り直す。

## 2. 判定

### 2-1. 新しい判定（球団生成300球団、架空球団用の日本人野手）
PR #110 の仕組み（「実在」の判定、誤差つきの合否、id）で作り、`run_checks.py` に組み込む。`scripts/check_fielder_batting.py`（打席）と `scripts/check_fielder_position.py`（ポジション）に節を足す。

| 項目 | 合格の範囲 |
|---|---|
| 対左投手のランクの割合（左打・右打、A〜G） | 各ランク 実在±4ポイント |
| 対左投手のランク点 左打・右打 | 実在±0.4 |
| ランク点の合計 左打・右打 | 実在±0.6 |
| 捕手のキャッチャーのランクの割合（A〜G） | 各ランク 実在±5ポイント（誤差つき） |
| 捕手のキャッチャーのランク点 | 実在±0.4 |

- 個別生成（架空球団用・野手5000人）は参考として同じ表を出す。

### 2-2. 検証の進め方（PC の負荷を減らす）
- 調整中は、`check_fielder_batting.py`・`check_fielder_position.py` だけを流す（`--quick` でも可）。`run_checks.py` 全体は流さない。
- 値が決まったら、変えていない区分（個別生成の架空球団用の投手、ドラフト候補用・助っ人外国人用の投手と野手）が seed 1〜1000 で改修前と完全に一致することを確かめる。
- 一致したら、それらの区分だけを使う判定（`check_draft_balance.py`、`check_foreign_balance.py` の個別生成の項目、投手だけの判定など）は流さず、スナップショットもそのままにする。どれを省いたかを報告する。
- 正式な規模で流すのは、架空球団用の野手か球団生成を使う判定だけ。1回だけ流し、スナップショットを更新した後の確認は、更新した項目の値がスナップショットと一致することの確認で済ませる。
- 並列数を指定できるなら、PC を使いながら流せる程度に下げる。

### 2-3. 既存の判定の扱い
- ランク特能・査定・戦力・背番号で「悪化」が出るのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけ `--update-snapshot --only ... --reason` で更新する。
- 動いてはいけない項目（野手の能力・特能、投手、外国人、ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定: `check_age_profile.py` の野手のランク点の年齢帯（要注意の「ランク点の年齢帯」を含む）、`check_fictional_balance.py` のランク特能の分布、`check_fielder_position.py` のポジションごとの査定、`validate_team_mode.py` の戦力レベル・散らばり・背番号。
- 判定の範囲は実在から決めたまま動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- 架空球団用の野手: 名前・年齢・ポジション・投打・能力・弾道・特能が改修前と一致する。変わった項目（ランク特能、査定）を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。

### 2-5. 後片付け（ついでに）
- `data/config/accepted_deviations.json` の `validate_team_mode.strength.corr_pitcher_fielder`（PR #121 で受け入れ）を外す。PR #122 の流しで合格に戻っており、受け入れたときの理由（「どこかの改修で下がった可能性」）は、その後の調査（各 main で seed 1〜800 の相関 0.19〜0.21、差は誤差の範囲）で外れていたため。外したあとに要注意・不合格になるなら、外さずに報告する。
