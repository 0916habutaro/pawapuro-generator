# ランク特能の年齢の幅（B以上の数） 改修指示

## 目的

架空球団用の日本人の、年齢によるランク特能の**幅**を実在に合わせる。

- PR #127 で B の端を減らした結果、`check_age_profile.py` の「B以上の数：30〜33 が 0.6〜0.95」が要注意になった（球団生成の野手 0.577、個別生成の野手 0.573・投手 0.575）。
- 実在は、26〜29歳では B 以上が少なく、30歳を過ぎると B 以上も E 以下も増える（ベテランほど個性が出る）。生成は年齢による変わり方がなだらかすぎる。

年齢でランクを傾ける補正（`FICTIONAL_AGE_RANK_BETA`・`FICTIONAL_AGE_RANK_GAMMA`）を測り直す。対象は架空球団用の日本人（個別生成・球団生成）。外国人・ドラフト候補用、能力・特能は変えない。

**前提**: PR #127 をマージした後の main（2b8078e）で作業する。

## 1. 改修の内容

### 1-1. 年齢の傾き（β）と幅（γ）を変える
```
FICTIONAL_AGE_RANK_BETA
  野手  今: (20,−0.18) (23.5,−0.035) (27.5,0.012) (31.5,0.075) (36,0.025)
        新: (20,−0.18) (23.5,−0.035) (27.5,0.012) (31.5,0.055) (36,0.03)
  投手  今: (20,−0.12) (23.5,−0.06) (27.5,0.025) (31.5,0.04) (36,0.05)
        新: (20,−0.12) (23.5,−0.06) (27.5,0.025) (31.5,0.035) (36,0.04)

FICTIONAL_AGE_RANK_GAMMA
  野手  今: (20,0.045) (23.5,0.012) (26,0.0) (29,−0.008) (33,−0.008) (36,−0.004)
        新: (20,0.045) (23.5,0.012) (26,0.008) (29,0.002) (31,−0.028) (33,−0.028) (36,−0.005)
  投手  今: (20,0.055) (23.5,0.012) (26,0.0) (29,−0.012) (33,−0.014) (36,−0.004)
        新: (20,0.055) (23.5,0.012) (26,0.0) (29,−0.012) (33,−0.03) (36,−0.03)
```
- γ が負だと、D から離れたランク（B 以上・E 以下）が出やすくなる。野手は30〜33歳の幅を広げ、26〜29歳を少し狭める。β（平均の傾き）は、幅を広げて上がった分を下げる。
- 野手の γ に (31, −0.028) の点を足す（30〜33歳を同じ幅にするため）。`interpolate_age_chance` は点の数によらず使える。
- 重みを変えるだけで、乱数を引く回数は変えない。

試作で気づいたこと:
- **野手の26〜29歳のランク点のSDが 7.0 になる**（改修前 7.5）。`check_age_profile.py` の「ランク点SD：26歳以上の各帯が 7以上」の下限ちょうど。下回るなら、野手の γ の (26, 0.008)・(29, 0.002) を少し下げる（例 0.006・0.0）。

- 投手の E 以下の数は、どの年齢でも生成のほうが多い（生成 2.2〜2.4、2026年版の実在 1.7〜1.9）。2024〜26年版のランクごとの割合は合っているので、2026年版だけの傾向かもしれない。今回は直さない。

## 2. 判定

### 2-1. 対象の判定
新しい判定は作らない。`check_age_profile.py` の次の判定がすべて合格になること（範囲は今のまま）。
- B以上の数：30〜33 が 0.6〜0.95、〜21 が 0.15以下（球団・個別、投手・野手）
- ランク点：各年齢帯が目標±2.0、年齢との相関 0.20〜0.40、SD（〜21、26歳以上の各帯 7〜10）

あわせて、PR #127 の新しい判定（ランクの割合・ランク点、11区分）と、PR #124 の走力・肩力の帯ごとのランク点が合格のままであること。

### 2-2. 検証の進め方（PC の負荷を減らす）
- **PC で作業する**（外国人の名前のデータベースがクラウドにないため、球団生成の値が PC と合わない）。
- 調整中は `check_age_profile.py` だけを流す（`--quick` でも可）。
- 値が決まったら、変えていない区分（ドラフト候補用・助っ人外国人用の投手と野手）が seed 1〜1000 で改修前と完全に一致することを確かめる。一致したら `check_draft_balance.py`・`check_foreign_balance.py` は流さず、スナップショットもそのままにする。
- 架空球団用の投手・野手と球団生成を使う判定は、正式な規模で1回流す。スナップショットは流し終えた結果から書き込む（PR #125〜#127 と同じやり方）。更新した後の確認は、更新した項目の値がスナップショットと一致することで済ませる。
- 並列数は2程度に下げる。

### 2-3. 既存の判定の扱い
- ランク特能・査定・戦力・背番号で値が動くのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけスナップショットを更新する。
- 動いてはいけない項目（能力・特能、外国人、ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 判定の範囲は実在から決めたまま動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- 架空球団用の投手・野手: 名前・年齢・ポジション・投打・能力・弾道・特能・身長・体重が改修前と一致する。変わった項目（ランク特能、査定、背番号）を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
