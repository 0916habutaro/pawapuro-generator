# ランク特能の形（ポジション・役割ごとの重み） 改修指示

## 目的

架空球団用の日本人のランク特能について、ランク点の平均だけでなく**ランクの散らばり方**を実在に合わせる。

- 平均のランク点はほぼ実在どおりになった（PR #119〜#125）。ただ、ランクの割合を見ると、実在は D に集まっているのに、生成は B・F などの端が多い区分がある。
- いちばんはっきりしているのは捕手。実在の捕手は盗塁の87%、走塁の79%、ケガしにくさの77%が D だが、生成はそれぞれ62%・56%・57%（ケガしにくさは捕手のみ）。
- 投手の対ピンチ（特に先発）、野手のチャンスも、生成は B・F が多い。

対象は架空球団用の日本人（個別生成・球団生成の両方）の、走塁・盗塁・ケガしにくさ・チャンス（野手）と対ピンチ（投手）。外国人、ドラフト候補用、能力・特能、ほかのランク特能は変えない。

**前提**: PR #126 をマージした後の main（b29bb39）で作業する。洗い出し（`docs/洗い出し結果_2026-10-12.md`）の候補1。

## 1. 改修の内容

### 1-1. 重みの鍵を分ける
- `fictional_fielder_ranked_weights_key`（野手）に次を足す。
  - 走塁・盗塁: `"{group}_{まとまり}"`。まとまりは 捕手→`捕手`、一塁手・三塁手→`一三`、それ以外→`二遊外`（`FICTIONAL_FIELDER_RUN_GROUPS = {"捕手": "捕手", "一塁手": "一三", "三塁手": "一三"}`）。
  - ケガしにくさ: 捕手・遊撃手→`"ケガしにくさ_捕遊"`、それ以外→`"ケガしにくさ_他"`。
- `fictional_pitcher_ranked_weights_key`（投手）に、対ピンチ→`"対ピンチ_先発"`・`"対ピンチ_救援"`（中継ぎ・抑えは救援）を足す。
- 投手のケガしにくさは、今の `"ケガしにくさ"`（投手の表）のまま。

### 1-2. 重みを足す・変える（A／B／C／D／E／F／G）
`FICTIONAL_FIELDER_RANKED_WEIGHTS` に足す:
```

走塁_二遊外        4.5／9.2／21.8／60.4／4.0／0.11／0.1
盗塁_捕手          0.3／0.1／4.3／85.8／9.1／0.14／0.2
盗塁_一三          0.29／0.5／10.6／72.0／13.8／2.6／0.2
盗塁_二遊外        0.3／3.3／14.6／50.2／20.6／10.8／0.2
ケガしにくさ_捕遊  0.1／1.8／3.8／80.1／11.4／2.6／0.19
ケガしにくさ_他    0.1／2.4／4.3／61.4／25.4／6.2／0.2
```
`FICTIONAL_FIELDER_RANKED_WEIGHTS["チャンス"]` を変える:
```

```
`FICTIONAL_PITCHER_RANKED_WEIGHTS` に足す:
```

対ピンチ_救援  0.3／0.57／15.2／67.6／14.3／1.8／0.2
```
- 今の `"走塁"`・`"盗塁"`・`"ケガしにくさ"`（野手）・`"対ピンチ"` の重みは残す（鍵が見つからないときの予備）。
- 重みは「今の重み × 実在の割合 ÷ 生成の割合」を2〜3回繰り返して作った（container の `rfit.py`）。補正（選手格・走力との連動・年齢の傾き）を通した後の割合が実在に合うようにしてある。走塁の A だけは、実在が1%を超えるので A も合わせた。ほかの A・G は今の重みのまま。
- 重みを変えるだけで、乱数を引く回数は変えない（`weighted_choice` は重みによらず1回）。

## 2. 判定

### 2-1. 新しい判定（球団生成300球団、架空球団用の日本人）
PR #110 の仕組み（「実在」の判定、誤差つきの合否、id）で作り、`run_checks.py` に組み込む。走塁・盗塁は `scripts/check_fielder_speed.py`、ケガしにくさ・チャンスは `scripts/check_fielder_position.py`、対ピンチは `scripts/check_pitcher_rank_pitches.py` に節を足す。誤差は、同じ選手が複数の年版に入っているので、**異なる選手の数**で出す。

| 項目 | 合格の範囲 |
|---|---|
| 0章の11区分のランクの割合（B〜F） | 各ランク 実在±4ポイント（誤差つき） |
| 0章の11区分の D の割合 | 実在±6ポイント（誤差つき） |
| 0章の11区分のランク点 | 実在±0.3（誤差つき） |

- 個別生成（架空球団用・投手5000人・野手5000人）は参考として同じ表を出す。

### 2-2. 検証の進め方（PC の負荷を減らす）
- **PC で作業する**（外国人の名前のデータベースがクラウドにないため、球団生成の値が PC と合わない）。
- 調整中は、節を足した3本だけを流す（`--quick` でも可）。`run_checks.py` 全体は流さない。
- 値が決まったら、変えていない区分（ドラフト候補用・助っ人外国人用の投手と野手）が seed 1〜1000 で改修前と完全に一致することを確かめる。一致したら、それらの区分だけを使う判定（`check_draft_balance.py`、`check_foreign_balance.py`）は流さず、スナップショットもそのままにする。
- 今回は投手も変わるので、架空球団用の投手・野手と球団生成を使う判定は正式な規模で1回流す。スナップショットは流し終えた結果から書き込む（PR #125・#126 と同じやり方）。更新した後の確認は、更新した項目の値がスナップショットと一致することで済ませる。
- 並列数は2程度に下げる。

### 2-3. 既存の判定の扱い
- ランク特能・査定・戦力・背番号で値が動くのは想定内。悪化の一覧を全部確認し、**動いてよい項目／いけない項目**に分けて報告する。動いてよい項目だけスナップショットを更新する。
- 動いてはいけない項目（能力・特能、外国人、ドラフト候補）が動いた場合は、更新せずに報告して相談する。
- 特に確認する既存の判定: `check_age_profile.py` のランク点の年齢帯・年齢との相関（投手・野手）、`check_fielder_speed.py` の走力・肩力の帯ごとのランク点（PR #124）、`check_fielder_batting.py`・`check_fielder_position.py` のランク特能（PR #123）、`check_pitcher_rank_pitches.py` の先発・救援のランク特能（PR #119）、`check_fictional_balance.py` のランク特能の分布、`validate_team_mode.py` の戦力・背番号。
- 判定の範囲は実在から決めたまま動かさない。合格にならない項目があれば、値と範囲を報告する。

### 2-4. 変わらないことの確認
- 架空球団用の投手・野手: 名前・年齢・ポジション・投打・能力・弾道・特能・身長・体重が改修前と一致する。変わった項目（ランク特能、査定、背番号）を人数つきで一覧にする。
- `tests/test_hash_independence.py` が通ること。全テストを流し切り、成功・失敗の件数を報告する（失敗0件にしてから報告する）。
